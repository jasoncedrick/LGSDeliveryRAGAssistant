T07 NEXT STEP: INDEPENDENT USEFULNESS REVIEW

Start here
Open human_review.json. It contains 60 existing development controls, in shuffled order, across five groups and all three language variants. Each item shows the question, reference answer and actual retrieved passage. Model outputs, old labels and original case IDs are deliberately absent. No reviewer name is requested.
Do not open PRIVATE_comparison_key.json or old model outputs while completing the review. packet.snapshot.json is the untouched integrity copy; leave it unchanged.

For each item, edit only decision and notes
decision: "useful", "not_useful", or "uncertain".
notes: one brief reason referring to what the ACTUAL RETRIEVED CONTEXT states or omits.
Example formatting only: "decision": "not_useful", "notes": "Only a service heading; no requested fee or condition is stated."
Judge each actual passage; do not copy this example decision across items.

Criterion
Useful: the context directly supports at least one fact requested by the question, consistent with the reference. It need not contain the complete answer.
Not useful: only a shared topic, office heading, cover page, unrelated service, or no requested fact. Reference-answer text is not proof that the retrieved context contains it.
Uncertain: the passage or reference is ambiguous, association is detached, the language is unclear, or source support cannot be determined. Do not infer an unstated rate, exception or relationship. Explain the uncertainty in notes.
Compare question -> reference -> actual context. The exact source metadata is retained in the separate key for later source checks; this task primarily judges the text actually supplied to the model. Flag a doubtful reference as uncertain rather than inventing a resolution.

After all items
Set independent_human_review_completed to true only after an actual human has reviewed all 60 items.
Fill review_basis with a short description of the review process and any prior familiarity with the labels/reports. No name is needed. This is independence from automated judgments, not a claim of independent expert certification. Disclose any prior role in creating labels.
Keep all question, reference and passage fields unchanged.

Then run from the clean project
D:\thesis\venv\Scripts\python.exe -B scripts/review_t07_judge_controls.py --compare-output t07-independent-judge-comparison-v1

The comparison command rejects missing decisions, missing notes, changed source fields, duplicate IDs or an incomplete human-review attestation. It reports evaluator validity, human uncertainty and agreement separately. It does not fill missing RAGAS values, change old labels or choose a final system. Further outputs require fresh folder names.
