FACILITATOR PROTOCOL - T08/T09 VERSION 1

Prepare formal sessions after acknowledging the sample timing disclosure in
READ_THIS_FIRST.txt. This is an operational protocol, not a claim that all
implementation details appear literally in Chapter 3.

ROLES AND MASKING

The data custodian keeps private/ and the A/B mapping. The blinded facilitator
receives only these instructions, the fictional training handout and distribution
ZIPs. Raters receive only their own ZIP. If the same researcher has seen the
mapping or can identify archived responses, disclose that limitation. Do not
claim the facilitator was blinded merely because the UI hides configuration IDs.

Use codes R01, R02, R03; the software does not request reviewer names.
Confirm at least three independent government-service domain experts with
fluency across the study languages. Each scores all 120 outputs.
Do not let formal raters share judgments or see automated scores.

BEFORE THE FIRST FORMAL SCORE

Explain the relevance/faithfulness distinction with the existing fictional
MOCK_RATER_HANDOUT.txt in experiments/t08-t12-rater-preparation.
The examples are English-only practice, not government evidence or study data.
Ensure the multilingual panel understands the rubric and interface vocabulary.
Clarify procedure during practice, then use the same instructions for all raters.
Do not adjust the rubric after seeing formal outcomes.

Check one source link opens on each device. Desktop Edge/Chrome is recommended
for side-by-side review; mobile stacks the same two responses vertically.
Allow breaks after each 20 query pairs. Determine session duration through
practice; do not promise a fixed time or pressure raters to rush.

SOURCE SUPPORT

Common sources are exact official PDFs hash-matched to the frozen corpus
provenance. Starting pages derive from original source annotations, not new
retrieval rankings or answer-quality inspection. They are not an exhaustive,
independently certified answer key. The complete PDFs are available.

SCORING DISPOSITIONS

Standard case: two independent integer scores, each 1-4.
Equal scores for the two answers are permitted; there is no forced winner.
Explanation/citation notes and error flags are available, and are especially
useful for factual errors or evidence conflicts.

SAVE, RETURN, AND PRESERVE

At breaks: Download backup. Browser storage may be cleared or unavailable and
is not the authoritative research archive.
On another device: extract the same ZIP and Import backup. The interface rejects
different-rater/packet files. Import replaces local state after a confirmation;
download a backup first if both versions need to be retained.
At completion: Export final JSON and Export final CSV. Keep originals and return
both. JSON retains exact notes; CSV safely escapes formula-like text.

The researcher validates exports using COLLECT_RATINGS.ps1. Keep independent
original ratings intact. Any later adjudication belongs in a separate record,
not an overwrite. The collector leaves system IDs masked.

FOLLOWING TASKS

T10: three independent formal reviews of all 120 responses (360 response records).
T11: ordinal Krippendorff alpha separately for each dimension, with observed
counts and missingness. The manuscript's target is >=0.80; report actual results.
T12: establish the analysis plan before unmasking; keep scenario/language/rater
dependencies in the paired comparison. A favorable result is not guaranteed.

Do not launch another model run or retune on these held-out audit findings.
